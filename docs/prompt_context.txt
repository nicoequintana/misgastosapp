
# 🚀 Prompt de Desarrollo — Etapa 2 — Integración n8n → Mis Gastos

## 🎯 Objetivo
Implementar una integración backend que permita recibir gastos automáticamente desde un workflow de n8n (originado por mensajes de WhatsApp) y persistirlos en la aplicación **Mis Gastos** como si fueran cargados manualmente desde la UI.

La nueva funcionalidad **NO debe romper bajo ninguna circunstancia ninguna funcionalidad existente** (CRUD, dashboard, mock mode, UI, cálculos, estilos, etc).

Todo debe ser implementado respetando la arquitectura actual del proyecto.

---

## 🧱 Alcance Técnico

### 📌 Nuevo Endpoint Backend
Crear un endpoint público:

```
POST /api/integrations/n8n/gasto
```

Este endpoint recibirá gastos variables generados por n8n.

---

### 📥 Contrato de Entrada (Payload)

```json
{
  "descripcion": "Supermercado Coto",
  "monto": "28540,50",
  "categoria": "Alimentos",
  "medioPago": "Tarjeta Crédito"
}
```

#### Reglas:
- `descripcion` → obligatorio (string)
- `monto` → obligatorio (string o number)
- `categoria` → obligatorio (string)
- `medioPago` → obligatorio (string)
- `tipo` → siempre debe ser `"variable"` (setearlo desde backend)
- `fecha` → debe asignarse automáticamente usando la fecha actual del servidor

---

### 🔄 Normalización de Datos

- El campo `monto` debe normalizarse:
  - Aceptar coma o punto decimal.
  - Convertir siempre a número válido.
  - Rechazar valores inválidos (NaN, negativos, vacíos).

- Los strings deben:
  - Trim de espacios.
  - Normalización básica (evitar strings vacíos).

---

### 🛡️ Anti-Duplicados (Idempotencia)

Debe evitarse la creación de gastos duplicados **exactamente iguales**.

Se debe:
1. Generar un fingerprint/hash combinando:
   - descripcion
   - monto normalizado
   - categoria
   - medioPago
   - fecha (YYYY-MM-DD)

2. Persistir ese fingerprint.
3. Si ingresa un request con el mismo fingerprint:
   - No crear un nuevo gasto.
   - Responder indicando que fue duplicado.

Idealmente:
- En Supabase: usar unique constraint.
- En Mock Mode: validación en memoria.

---

### 🗄 Persistencia

La app debe seguir funcionando en dos modos:

#### ✅ Producción
- Usar Supabase PostgreSQL.
- Preparar correctamente el código para conexión (aunque la configuración real se hará luego).

#### ✅ Mock Mode
- Persistencia en memoria.
- El nuevo endpoint debe funcionar también en este modo.

---
